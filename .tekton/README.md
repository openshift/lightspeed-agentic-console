# Unit coverage, lint, and Codecov (OLS-4823)

`unit-test-coverage-pull-request.yaml`, `unit-test-coverage-push.yaml`,
`lint-pull-request.yaml`, and `lint-push.yaml` are standalone
Pipelines-as-Code PipelineRuns. They run independently of the image
build, for every PR targeting `main` and every push to `main`, respectively.
No image build or IntegrationTestScenario is required. They are not labeled as
build pipelines and do not produce application snapshots. The lint runs
(`npm run lint` + `npm run type-check`) execute in parallel with the unit
coverage run, giving immediate from-source feedback that does not wait for
the image build and snapshot required by the
`.tekton/integration-tests/lightspeed-agentic-console-pre-commit.yaml`
ITS pipeline. The lint runs cover `npm run lint`, `npm run type-check`,
and a checked `npm run i18n`: the locale catalogs are regenerated and the
pipeline fails if the committed `locales/` tree differs, so stale
translations cannot merge. The i18n regeneration is deterministic on a
clean checkout (verified locally) and requires no network beyond `npm ci`.

The public source repository is checked out at the event's exact revision.
The existing `npm run test-coverage` target runs only the vitest unit suite
(`src/**/*.test.{ts,tsx}`) and never the Playwright E2E/integration tests.
Coverage is generated by `@vitest/coverage-v8` into
`coverage/cobertura-coverage.xml` and covers `src/**` TypeScript source,
excluding test files, mocks, and the test setup.

## Secret setup

Create a repository-specific Codecov upload token for
`openshift/lightspeed-agentic-console`. In Konflux namespace
`crt-nshift-lightspeed-tenant`, create an Opaque secret:

- Name: **`ols-codecov-token-lightspeed-agentic-console`**
- Key: **`CODECOV_TOKEN`**
- Value: the repository's Codecov upload token

The PipelineRuns use the existing `build-pipeline-lightspeed-agentic-console`
service account. The token is injected only into the upload step, not checkout
or unit tests. It is required: a missing secret/key prevents the upload step
from starting. Do not commit the token or reuse another repository's token.

As with any token-bearing PR pipeline, only run it for trusted/approved PRs.
Step-scoped injection is not a security boundary against malicious source:
the PR controls the uploader and shares files with the upload step. Retain
PaC's untrusted-contributor approval controls; review pipeline/uploader changes
before approving a run. No GitHub checkout credentials are needed for this
public repository.

## Upload policy and validation

`scripts/codecov.sh` follows the shared lightspeed pinned Codecov CLI (11.3.1),
bounded retry/timeout, and clearly logged soft-fail upload policy. A unit-test
failure blocks the pipeline; a Codecov service/upload failure does not.
`.codecov.yml` mirrors lightspeed-service's non-blocking status/comment policy.
The pipeline supplies the source SHA, PR source branch and number, or `main`
for baseline uploads, plus the explicit `openshift/lightspeed-agentic-console`
slug. The legacy Prow-style environment variable names are the uploader's
interface; this does not run in Prow. `npm run test-coverage` never uploads
locally.

After the first main push, confirm the baseline in Codecov. Then open a PR
and confirm an upload for its head SHA and a PR coverage delta/comment. Ensure
the Codecov GitHub integration is enabled for this repository. Local validation
cannot establish these acceptance criteria or prove tenant admission/network
policy permits the PipelineRuns; the first Konflux run must verify those.

Both manifests within each pair intentionally run on all changes to keep the
PR check and main baseline consistent. Their task specifications are
identical; keep them in sync when changing execution steps. All steps use the
UBI nodejs-22-minimal image, which supplies Node.js 22, npm, curl, and tar,
but no Git, gzip, or Python — and packages cannot be installed in it without
root. The pipelines compensate as follows (all verified locally inside the
image, running as a non-root user):

- **checkout** downloads the exact commit tarball from
  `codeload.github.com` with curl, decompresses it with node's built-in
  zlib, and extracts it with `tar --strip-components=1`.
- **dependency install** runs `npx -y 'npm@^11' ci`: the image bundles
  npm 10, but the repository lockfile requires npm >= 11.10. The `^11`
  range resolves to the latest npm 11.x at run time (no patch pin); the
  same requirement is satisfied elsewhere in the repository by image
  choice (the pre-commit ITS pipeline's playwright image ships npm 11)
  and by the hermetic offline Docker build.
- **coverage upload** downloads the pinned `uv` 0.10.0 release tarball
  (decompressed via node zlib), and `uv` provisions its own CPython to run
  the Python-based codecov CLI. The uploader passes
  `--auto-load-params-from GithubActions` so the CLI skips CI
  auto-detection: its local adapter shells out to git, which the minimal
  image does not have, and all upload parameters are supplied explicitly
  anyway.
